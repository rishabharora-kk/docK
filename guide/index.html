Add a draggable dock with your AI assistant

docK is a macOS-inspired dock interaction with spring animation, drag-to-reorder, removal, and undo. The repo pairs a working HTML reference with a motion specification so your assistant can reproduce the behaviour in your own project.

1. Try the reference

Open the interactive dock. Drag sideways to reorder. Drag upward to remove an icon, then undo. With a keyboard, Tab to an icon, press Space to pick up, use the arrow keys, then press Space to drop. Escape cancels.

2. Give your assistant this prompt

Add this dock interaction to my project: https://github.com/rishabharora-kk/docK
Read IMPLEMENTATION.md, spec.json, and index.html from the repo.
Adapt it to my stack and existing design, preserve pointer and keyboard
behaviour, and verify the interaction scenarios. Use my app's icons and actions.

Your assistant needs access to repository files. If it cannot read a GitHub page, it can clone the repository or read the raw implementation guide. The link provides the context; it does not automatically install software or connect MCP.

Which frameworks can I use?

The shipped demo uses HTML and vanilla JavaScript. The optional MCP server includes build-plan notes for React, Vue, Svelte, and SwiftUI. Those plans guide an implementation; docK does not currently ship installable components for those frameworks.

For component frameworks, keep per-frame physics out of render state, use one animation loop, and clean it up on unmount. Preserve the landing slot, deferred commit, active-pointer isolation, focus continuity, reduced motion, and undo.

Optional: connect the MCP server

MCP stands for Model Context Protocol. An MCP-capable coding client can run docK's Python server locally over stdio. Reading the files directly is sufficient if you do not want to configure it.

git clone https://github.com/rishabharora-kk/docK.git
cd docK
python -m venv .venv
# macOS/Linux:
.venv/bin/python -m pip install -r requirements.txt
# Windows:
.venv\Scripts\python.exe -m pip install -r requirements.txt

Use the Python executable in that environment and the absolute server path in your client's MCP settings. This common configuration shape may need adapting to the client:

{
  "mcpServers": {
    "dock": {
      "command": "/absolute/path/to/docK/.venv/bin/python",
      "args": ["/absolute/path/to/docK/server.py"],
      "env": {"DOCK_REPO_URL": "https://github.com/rishabharora-kk/docK"}
    }
  }
}

Read dock://spec and dock://reference, or start with the build_dock_pick_drop prompt. Tools include get_spec, get_build_plan, load_from_repo, and check_implementation.

The static checker looks for source-code patterns. It can catch omissions, but it cannot prove correctness, accessibility, or parity with the demo. Native framework code can produce false failures. Run the interaction scenarios.

What should I verify before shipping?

Check tap, reorder, boundary jitter, removal, undo, Escape, pointer cancellation, a second pointer, re-grabbing during settling, keyboard focus, reduced motion, and one-icon behaviour. Test your real app on a physical touch device. Replace sample app names and tap feedback with your own intended actions.
